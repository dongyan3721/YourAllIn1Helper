# 密码本 M0 审查决定（2026-10-25）

审查对象：WorkBuddy / Kimi K3.1 Pro 的 `ac48dc6`、`6556a36`。审查与集成：OpenAI Codex。

**结论：接受 M0 设计交付，允许按下列约束进入 M1；这不等于密码本实现或安全验收通过。当前不挂载 password_vault，不允许使用真实秘密。**

1. 冻结 v1 为随机 DEK、主密码 KEK 包装、逐字段独立信封和规范 AAD；所有用户内容加密，明文仅保留必要操作元数据。记录更新重加密所有现存字段，事务提交与版本检查不可拆开。
2. 接受 `argon2id-v19-m65536-t3-p4` 作为待实测 profile，KDF 并发限制为 1，参数有界，UI 不阻塞；不以未经测量的解锁耗时作承诺。该参数与 [RFC 9106](https://www.rfc-editor.org/rfc/rfc9106.html) 的较低内存推荐一致。
3. 每次 AEAD 调用生成独立 nonce，采用 OS CSPRNG 并明确失败；长度、字段和 AAD 严格检查。`UNIQUE(entry_id, nonce)` 不是全 DEK 唯一性证明，不能这样宣传；测试须注入重复值和随机失败。实现使用的确切 RustCrypto 版本须锁定、复核 [AEAD/nonce 契约](https://docs.rs/aes-gcm/latest/aes_gcm/)。
4. M1 仅实现主密码闭环；生物识别控件明确不可用。macOS 带 ACL 的 Keychain 设备槽留在 M2。Windows DPAPI + Hello 可以作为单独标注的便捷解锁设计继续研究，但不宣称 Hello/TPM 密码学门控；[DPAPI 官方边界](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata)不能被认证成功布尔值替代。
5. 主密码变更成功后强制当前会话重锁；设备槽重注册/撤销策略在 M2 单独验收。锁定 epoch、迟到结果、路由离开/窗口关闭/休眠及停用清理是 M1 必需项。原生能力查询失败必须锁定；当前时长适配器的 CLI 锁状态缺口不能被当成已解决。
6. 共享剪贴板保护与条件清理服务尚未实现；M1 秘密复制入口必须禁用并说明原因，不能暂用 AtomicBool 或文本比较顶替所有权。原生剪贴板服务完整审查后再接入。
7. 新增空表迁移不得触碰旧模块；破坏性/重加密迁移、恢复和 DEK 轮换不属于首个 M1 版本。需要这些操作时先落地“备份失败中止”策略，不私改共享连接 PRAGMA。不存在自动修库/自动导入用户密码的路径。
8. M1 在独立 worktree、虚构数据完成密码学向量/篡改/IPC/生命周期测试和前端短驻留检查后再审查。依赖级清理、跨进程明文副本和硬件平台限制均必须保留真实边界，不声称全进程物理清零。

下一轮实施基线应使用完成本次集成验证后的提交；不要在 M0 旧基线自行复制其他成员的适配器。实施交接必须列出独立测试、原生能力与 GUI 三层证据，未测项保留。
