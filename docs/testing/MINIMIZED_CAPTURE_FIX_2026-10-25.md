# 最小化后 F1 截图报 kernel error（2026-10-25）

## 根因与复现

主窗口最小化后按 F1。遮罩没有进入可框选状态，界面提示 `Internal kernel error`，长图预览无法向下滚动。把主窗口从 Dock 恢复后，同一条错误仍在。

统一日志里，`all-in-one-desktop` 在 2026-10-25 20:39:34 把主窗口标为不可见，并在同一时刻创建遮罩页、发起屏幕采集。20:43:40 出现 `SLSTransaction decode timed out`（SkyLight，error 268451843）。应用没有把 `tracing` 写到文件，所以界面上的 kernel error 对应该错误的包装，而不是另一条业务日志。

macOS 全局热键回调跑在 AppKit 主线程。F1 在这条回调里同步抓屏并创建全屏遮罩。遮罩页画完冻结帧后，要 `run_on_main_thread` 等主线程把窗口显示出来，最多等 5 秒。主窗口最小化时窗口服务拖住主线程，等待超时。`CoreError::Internal` 的展示文案是 `Internal kernel error: …`。前端把这次失败留在遮罩上，稍后即使窗口已经显示也不清除，所以恢复主窗口后错误还在，选区和预览都无法继续。

长图预览还有独立的布局问题：预览区是固定高度 flex 容器里的子项，默认 `min-height: auto`，外层 `overflow: hidden`。高图把子项撑开后被裁掉，容器内部没有溢出，滚动条不会出现。

## 修复

- `screenshot:` 热键改到后台线程执行，热键回调立刻返回。主线程只处理窗口创建和显示，不再在抓屏期间占住事件循环。
- 显示遮罩时激活应用，并只把遮罩自己从最小化状态恢复。若激活把已经最小化的主面板一起拉回前台，随即把它缩回 Dock，避免挡住选区。`set_focus` 失败不再中断显示。
- 冻结帧已经画上、显示握手的重试成功时，清掉遮罩上的瞬时错误。帧数据本身失败时仍保留错误并允许取消。
- 长图预览区设置 `min-height: 0`，图片按内容高度排列，预览窗口可以向下滚动。

## 验证

- 用户重新编译 App 后确认：最小化、按 F1，截图恢复正常，kernel error 不再留下。
- `cargo check -p all-in-one-host --offline` 通过。
- 本轮没有重新打包，没有把桌面截图放进仓库。完整截图 GUI 清单仍待验收，不能把这一次热键复测写成全部通过。
